# Python 3.14 / 3.15 Port Plan

**Status:** implementation complete locally; all local tests pass; GitHub CI/wheel runs pending
**Target:** CPython `>=3.14`; primary target **3.15**
**Policy:** no support for Python `<3.14`; official Kivy 2.3.1 remains the option for older interpreters
**Wheels:** low priority; source builds on 3.14/3.15 are the priority
**Last updated:** 2026-11-01

### External blocker decisions (2026-11-01)

**D1 — Windows 3.15 / `kivy_deps`: repackage the data-only wheels.**
- **Decision:** publish or consume `py3-none-win_amd64` wheels (interim: `cp315-cp315-win_amd64`) built from the existing cp314 payloads for `sdl2`, `sdl2_dev`, `glew`, `glew_dev`, `angle`, `gstreamer`, and `gstreamer_dev`. Use a local/private wheelhouse for development and CI, and request upstream publish generic wheels.
- **Why:** the inspected cp314 wheels for `sdl2`, `sdl2_dev`, `glew`, `glew_dev`, and `angle` contain only DLLs, headers, `.lib` files, and `__init__.py`; there are no Python extension modules or ABI-specific artifacts. The cp-tag is only packaging metadata. GStreamer should be verified before repacking, but follows the same pattern.
- **Fallback:** build against system SDL2/GLEW (`KIVY_SDL2_PATH` plus MSVC `INCLUDE`/`LIB`) and use the GLEW backend. This requires more setup and is not preferred.
- **Tasks:** write a repack script, record hashes, add a wheelhouse/find-links path for Windows 3.15, and file an upstream request for `py3-none-win_amd64` or cp315 wheels.
- **Status:** `[~]` decision made; implementation is part of M2.

**D2 — `ffpyplayer` on 3.15: source build first, gate only if necessary.**
- **3.14:** pin `ffpyplayer>=4.5.4`; 4.5.4 has cp314 wheels.
- **3.15:** build 4.5.4 from sdist with FFmpeg and Cython >=3.3 (patch the sdist's `cython~=3.1.8` build requirement if needed).
- **Fallback:** gate `ffpyplayer` to `<3.15` in the `media`/`full` extras, document that ffpyplayer-backed video is unavailable on 3.15, and rely on gstreamer/SDL providers where available. Track upstream cp315 wheels; the upstream repo is active (last push 2026-10-31).
- **Note:** Windows `full` uses GStreamer, not ffpyplayer, so this decision affects Linux/macOS only.
- **Status:** `[~]` decision made; implementation is part of M2.

**D3 — free-threaded `3.15t`: out of scope for the initial port.**
- **Decision:** do not add `3.15t` to CI, `requires-python`, or the support claim. Revisit after the GIL 3.14/3.15 builds are green and Cython, SDL, `kivy_deps`, `pywin32`, and `ffpyplayer` are verified.
- **Why:** no stated requirement, and the binary dependency chain has no free-threaded wheels.
- **Status:** `[x]` decided.

**D4 — RPi/armv7 wheels: defer/drop.**
- **Decision:** remove RPi wheel builds from the port scope. Keep the RPi Dockerfile/job unchanged only until it becomes a CI blocker, then disable it rather than porting it in this pass.
- **Why:** wheel builds are low priority, the base images do not provide 3.14/3.15, and cross-building SDL/GStreamer is high effort.
- **Status:** `[x]` decided.

**D5 — prebuilt wheels / cibuildwheel 3.15: defer.**
- **Decision:** source builds are the acceptance criterion. Upgrade cibuildwheel to 4.x for 3.14/3.15, but do not make wheel availability a gate. Add cp314/cp315 wheel jobs after the source-build matrix and tests are green.
- **Why:** user priority; wheel builds can lag dependency availability.
- **Status:** `[x]` decided.

**D6 — pure-Python and optional dependencies: test, then patch or mark the extra unsupported.**
- **Decision:** verify `Kivy-Garden`, `oscpy`, `docutils`, `pygments`, `requests`, `filetype`, pytest plugins, PyInstaller hooks, Sphinx, and `sphinxcontrib-jquery`. If one is broken, prefer a small patch/fork; if the fix is not cheap, mark only that optional extra unsupported on 3.15 rather than blocking core.
- **Status:** `[ ]` verification in M2.
